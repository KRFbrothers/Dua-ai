Before → after

The old surface was static; the new one is alive.

Before

Static wash + three grey dots

A fixed vertical gradient, one static wave path and a static violet glow. The only motion was a 500 ms cross-fade between Chat and Task. Loading was three 8 dp dots on a 1200 ms alpha loop.

After

Drifting blobs + glowing orb

Four soft blobs — blue, purple, magenta, orange — orbit on slow ellipses over a tinted base. Loading is a multicolour orb with a rotating sweep gradient and a breathing glow.

Thinking

Palette

Two ramps: saturated for dark surfaces (the gradient must emit light), pastel for light surfaces (it must tint, not glare).

Motion budget

Deliberately slow, so the eye reads it as "alive" rather than "moving".

Why it stays cheap

Brushes built once

Every Brush and the sparkle Path are created inside drawWithCache, so they are constructed only when the size or theme changes — never per frame.

Draw-phase only

The animated values are read inside onDrawBehind. A frame invalidates only the draw — composition and layout are skipped, so the chat list, composer and messages are never recomposed.

A handful of GPU primitives

The backdrop is one rect plus four drawCircle calls under a translate transform. The orb is three circles plus one small path. No per-frame allocation, no path building.

Respects "Remove animations"

Both layers call the existing rememberMotionAllowed(). When the system animator scale is 0, the infinite transition is not created at all and the layer renders as a single static frame.
