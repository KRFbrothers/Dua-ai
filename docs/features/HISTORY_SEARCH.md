# Chat history search

Open the history menu and enter a word or literal phrase in **Search chats**. Search now covers the current project's cached chat titles, user messages, assistant replies, drafts, and saved Run code source/output, including text beyond the title and last reply. Markdown/code fences are searched as text. Matching is case-insensitive, with surrounding query whitespace ignored; it is not regex, fuzzy or semantic search.

Long-press a recent chat → **Rename** → edit **Chat name** → **Save**. Names allow 1–120 UTF-16 code units on a single line; surrounding whitespace is trimmed. Renaming keeps the original messages and chat ID. Older chats retain their derived titles. Custom titles survive restart, JSON backup/import and the existing authenticated Cloud Sync flow; saving locally does not claim that a cloud upload has completed. Refresh setup after deploying the matching backend before renaming. Finish an active reply or sync review before saving a name.

The drawer shows each matching chat once by title, with pinned chats first and then newest updates. While search is open, destination rows are hidden so results start directly below the field and All/Pinned filter. **Clear chat search** restores the unfiltered titles within the selected filter and focuses the input. The keyboard Search action dismisses the keyboard while keeping the query/results. Closing search restores the browsing position and destination rows. Tap a result to open that conversation normally; opening does not jump directly to the matching turn. Queries allow up to 200 UTF-16 code units. The search helper can produce snippets, but this drawer does not render snippets or highlighted matches.

## Pinned chats

Long-press a recent chat → **Pin**, or use its inline pin button when available. Pinned chats appear first with a pin icon. **Unpin** returns the conversation to its position by last update. **Filter chats** selects All chats or Pinned chats and applies to search results too. Search uses the current project's cache. Pinning keeps the chat ID, title, messages and last-message timestamp unchanged.

Pins are optional Boolean chat metadata, retained in the phone cache, JSON backups/imported copies and the authenticated cloud snapshot. Saving a pin locally queues the existing sync flow; it does not claim a server upload has completed. Enable automatic sync or review/confirm an upload to sync pending pins. Automatic sync merges a changed pin against its last verified baseline without creating a recovered conversation for a pin-only edit; actual offline content conflicts still preserve copies. During a first sync, unverified cached pin values yield to the server; edits made during the first read remain protected. A reviewed download deliberately uses the server pin and does not create a copy for pin-only differences.

Deploy the updated backend and refresh setup before pinning: the Android action requires explicit `history.pin` support. Older snapshots without `pinned` default to false. Updated Android snapshots send explicit true/false so Unpin can sync; updated backend uploads from old APKs that omit the field keep an existing server pin. No SQL migration, provider call, storage permission or new automatic-sync consent is needed. Backend rollback can strip pin metadata; older APKs may ignore it or pause on the expanded sync baseline. Phone/live-production verification remains pending.

## Search within a conversation

Open a conversation → tap **Find in chat** in the top bar. Enter a literal word or phrase; matching is case-insensitive and trims surrounding whitespace. Search covers the active chat’s loaded user/assistant message text, Markdown/code fences, and saved Run code source/output. It returns one result per matching message in conversation order, showing a highlighted snippet and outlining the selected message. **Previous matching message** / **Next matching message** jump between results and wrap at the ends. A long message is positioned at its start; the snippet shows the match even when it is deeper in the message or in a collapsed Run code block.

The query is capped at 200 UTF-16 code units. Query changes are debounced by 150 ms; message updates are scanned on a background dispatcher with cancellation, without waiting for a streaming reply to finish. Search pauses automatic tail following, preserves the composer draft, and leaves the reader at the selected turn on close. **Latest reply** can return to the tail afterwards. Close search or use system Back; changing conversations clears its query and selection. Empty queries, no matches and a pending scan have distinct states. Query and selection use transient Android UI saved state, never cloud history or JSON exports.

This search makes no backend/provider request and requires no new permissions. It excludes unsent drafts, thinking, summaries, attachment contents, project memory/instructions and conversations absent from the phone cache. Use sidebar search for drafts and other conversations, and sync to refresh the server-backed cache.

## Server-first data and project scope

The owner server snapshot remains authoritative. Search runs on the phone's currently loaded cache, including unsynced draft edits; sync or reviewed download to refresh it. It cannot find server chats absent from that cache, deleted cached copies, raw stored-file contents, attachment text, thinking summaries, rolling summaries, project instructions or memory. It makes no provider/API request and does not create an index or write chat data. Query/snippets are transient UI state, not part of cloud snapshots or JSON exports; standard Android UI saved-state restoration can retain the query. Switching projects clears the query and scopes results before scanning.

The current drawer filters its supplied cache synchronously when the query, filter or chat list changes; it does not display a pending search indicator. Empty/cleared search returns cached chat titles within the selected filter. This differs from the debounced in-conversation search above. No extra background service, storage permission, migration or provider cost is added.

## Deleting a conversation

Long-press a recent chat → **Delete chat** → confirm. This requires owner sign-in and the updated backend's `history.delete` capability. The server removes only that conversation, preserving other chats, project definitions, notes and stored files. Its ID remains in server deletion metadata; stale uploads containing that ID are rejected with a conflict. Automatic sync and reviewed downloads remove cached copies with confirmed deletion IDs, including active drafts, without creating a recovered copy of the deleted chat. Offline devices apply this when they next sync.

The phone changes only after a confirmed response. Retry is safe if the server committed but the response was lost; cache-write failures report partial completion and let Retry finish. **Remove cached chat** remains a separate action and does not delete server history. Existing JSON exports/files and independently created conversation copies are retained. No database migration is required; deletion metadata lives in the existing revision-checked owner snapshot. Deploy the matching backend before using the updated APK. Rolling back to an older backend can remove these guards; repository tests do not verify production deployment or backup retention.
